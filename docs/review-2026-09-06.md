## 已修复的问题

| 优先级 | 触发条件与影响 | 修复位置与行为 |
| --- | --- | --- |
| P1 | 打开连接时，远端 multipart upload 没有对应的本机会话任务，会被自动 abort；这可能是其他客户端的有效上传。 | `app-store.ts` 的 `autoRecoverTasks` 只恢复本机任务，不自动清理未跟踪的远端上传。 |
| P1 | 在连接 A 执行操作、切到 B 后撤销，原全局历史会按 B 的 session ID 执行删除/移动。 | `setCurrentSession` 在连接改变时清空撤销/重做历史。 |
| P1 | 恢复下载时，本地文件比 checkpoint 长会重复追加，过短或偏移超过对象大小也没有校验；异常 Range 响应可能形成损坏文件。 | `open_download_file` 校验偏移和本地长度、截断未确认的尾部；前端取本地长度和已保存进度的较小值；校验返回长度，同次下载用 If-Match 固定对象 ETag。 |
| P1 | 默认 Backspace 打开删除流程；弹窗和菜单内的 Enter/Delete 可能触发底层文件管理器。 | Backspace 返回上级；尊重已处理的事件，并跳过弹窗、菜单、输入和交互控件。 |
| P2 | 新建/编辑连接后，回调闭包中的 sessions 仍是旧列表，保存成功却未打开连接。 | 欢迎页从最新 Zustand snapshot 查找会话再打开。 |
| P2 | 暂停/取消后的后端失败回调，会覆盖用户中断状态；恢复的 paused 任务原本被映射为 pending。 | 原生上传及恢复分支识别用户中断；增加独立 paused 状态及任务栏暂停/恢复入口。 |
| P2 | 日志 message 直接拼接对象 key、路径、任务 ID；metadata 白名单还保留文件名和部分 ID。 | 调整存储/传输日志，移除敏感字段插值；前端脱敏覆盖名称、ID、路径、原始错误及配置，保留计数等诊断数据。 |
| P2 | 通用图标依赖 Iconify 的在线 API；PDF worker 依赖 CDN。 | 图标改用已安装的 lucide-react，worker 本地打包。 |

## 仍需处理的发现

1. **P1：跨连接大文件复制会占用整个对象大小的内存。** `src-tauri/src/main.rs` 的 `transfer_object_between_sessions` 调用 `get_object` 收集完整 body，然后 `put_object`。多 GB 对象可能耗尽内存，超过单次 PUT 上限也无法工作。应单独实现流式读取与 multipart 目标写入，并补齐取消、进度和失败清理。当前修复未改变这条传输架构。
2. **P2：大目录仍存在等待与渲染瓶颈。** `src/stores/app-store.ts` 的 `listAllDirectoryPages` 在首屏更新前拉完所有分页；`src/components/file-explorer/FileList.tsx` 的 grid 分支直接映射全部文件，只有 list 分支使用虚拟列表。应将逐页展示和网格虚拟滚动一起实现。当前没有以真实 1 万对象 bucket 验证性能。
3. **P2：跨重启的下载恢复未持久化原始 ETag。** 本次 If-Match 可避免同一轮下载期间对象变化；若对象在暂停期间被替换，现存文件前半段仍可能来自旧对象。后续应在任务中保存 ETag/version ID 并在恢复前核对。当前 checkpoint 校验不等于文件内容完整性验证。

## 多窗口专项审查

- 动态窗口现在匹配 `manager-*` capability，并保留创建 webview、设置标题和聚焦窗口所需的权限；标签页 URL 对 session ID 做 URL 编码，窗口标签使用 UUID，避免同毫秒创建时冲突。
- 标签拖出采用带超时和重试的目标确认协议。目标窗口只在完成会话解析、插入标签并完成导航后发送 ACK；源窗口收到 ACK 才删除原标签，超时或目标不存在时原标签保持不变。重复投递按 transfer ID 去重。
- 标签拖放使用独立 MIME 类型，跨窗口请求包含源窗口和目标索引；成功投递、Escape 和零坐标取消会跳过拆分。原生文件拖放只监听当前 webview，异步注册在 StrictMode 卸载后也会清理。DOM 投递优先用于跨窗口合并；全局坐标 fallback 尚需混合缩放显示器实测。
- 每个窗口保留自己的标签、路径、选中文件和撤销历史；Rust 端任务记录按窗口分配，恢复/暂停/取消/删除会校验 owner，同一任务和同一本地目标文件不能在两个窗口并发执行。窗口关闭会经过前端和 Rust 双重检查，活动传输或任务创建未完成时关闭被阻止。
- 分片上传 ID 在创建远端 multipart 后立即记录，每个已完成分片和下载进度由 Rust 保存。前端不再通过异步进度回调重复写入这些 checkpoint，避免关闭/重挂载窗口导致遗漏或回写旧数据。
- session/profile/storage-backend 变更通过 Tauri 事件同步；每个窗口重新加载加密记录并 reconcile 本地标签，过期的 IPC 列表响应不会覆盖较新的结果。偏好存储按字段合并，避免一个窗口的 UI 写入覆盖另一个窗口的更改。
- 更新检查和安装按窗口保存 pending update；安装操作串行化并检查 channel/version，安装前阻止所有窗口仍有活动任务，下载进度仅发送到发起窗口。
- 新增 `tests/multiwindow.test.mjs`，通过独立模块缓存和模拟 IPC 覆盖慢启动窗口、重复传输、超时保留源标签、StrictMode 监听清理、路径/标签隔离、过期列表响应、拖放事件路由、任务创建期间暂停/取消、重复恢复、偏好合并和 capability。当前共 14 项通过；Rust 全套 9 项测试通过，其中新增 4 项覆盖任务 owner、重复启动、失败清理和下载目标互斥。CI 已加入 `pnpm run test`。
